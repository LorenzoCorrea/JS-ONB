1. O QUE É UMA FUNÇÃO (E POR QUE EXISTE)
========================================================
Uma função é um "mini programa" dentro do seu programa:
um bloco de código com nome, que só executa quando você
o chama.

Para que serve:
  - AGRUPAR código que faz uma tarefa específica
  - REUSAR esse código sem copiar e colar
  - ORGANIZAR o programa em pedaços com nome claro
  - Pegar algo (entrada), transformar, e devolver (saída)

Analogia do garçom:
  A função "garcom" sabe entregar um prato numa mesa.
  Você não reescreve o processo toda vez — só chama o
  garçom dizendo QUAL prato e QUAL mesa.

Sem função (repetindo código):
  console.log("Entregar Carbonara na mesa 10");
  console.log("Entregar Lasanha na mesa 12");
  console.log("Entregar Pizza na mesa 15");

Com função (escreve uma vez, usa sempre):
  function garcom(prato, mesa) {
    console.log(`Entregar ${prato} na mesa ${mesa}`);
  }

  garcom("Carbonara", 10);
  garcom("Lasanha", 12);
  garcom("Pizza", 15);


========================================================
2. ANATOMIA: DECLARAR x CHAMAR
========================================================
São DUAS coisas diferentes e ambas são obrigatórias.

DECLARAR (criar a função - ela ainda não roda):

  function garcom(prato, mesa) {
    console.log(`Entregar ${prato} na mesa ${mesa}`);
  }
  |________| |____| |__________|  |________________|
   palavra    nome   parâmetros      corpo (o que faz)
   reservada

CHAMAR / INVOCAR (aí sim ela executa):

  garcom("Carbonara", 10);
  |____| |______________|
   nome     argumentos

⚠️ REGRA DE OURO:
Declarar uma função NÃO a executa. Se você só declara e
nunca chama, nada acontece — o código dentro dela fica
"dormindo" esperando ser chamado.

E você pode chamar quantas vezes quiser:
  garcom("Pizza", 5);
  garcom("Pizza", 7);   // mesma função, outros valores


========================================================
3. PARÂMETROS E ARGUMENTOS
========================================================
Os dois nomes confundem, mas a diferença é simples:

  PARÂMETRO  -> o nome genérico na DECLARAÇÃO
                (a "caixinha vazia")
  ARGUMENTO  -> o valor real passado na CHAMADA
                (o que entra na caixinha)

  function garcom(prato, mesa) { ... }
                  ^^^^^  ^^^^  <- PARÂMETROS

  garcom("Carbonara", 10);
         ^^^^^^^^^^^  ^^   <- ARGUMENTOS

Dentro da função, o parâmetro funciona como uma variável
comum, já preenchida com o valor que você passou:

  function dobrar(numero) {
    console.log(numero * 2);
  }

  dobrar(5);    // dentro da função, numero vale 5  -> 10
  dobrar(100);  // dentro da função, numero vale 100 -> 200

Uma função pode ter zero, um ou vários parâmetros:

  function sayHello() {              // nenhum
    alert("Olá!");
  }

  function sayHello(nome) {          // um
    alert(`Olá ${nome}`);
  }

  function soma(a, b) {              // dois
    return a + b;
  }


========================================================
4. A ORDEM DOS PARÂMETROS IMPORTA
========================================================
O JS preenche os parâmetros pela POSIÇÃO, não pelo nome.

  function garcom(prato, mesa) {
    console.log(`Entregar ${prato} na mesa ${mesa}`);
  }

  garcom("Carbonara", 10);   ✅ "Entregar Carbonara na mesa 10"
  garcom(10, "Carbonara");   ❌ "Entregar 10 na mesa Carbonara"

O JS não reclama do segundo caso! Ele não sabe o que é
prato e o que é mesa — só copia na ordem. Trocar a ordem
é uma fonte clássica de bug silencioso.

Se você chamar com argumentos a MENOS, o parâmetro que
sobrou vira undefined:

  garcom("Carbonara");   // "Entregar Carbonara na mesa undefined"


========================================================
5. RETURN (DEVOLVER UM VALOR)
========================================================
return devolve um valor de dentro da função para quem a
chamou — é a "saída" da função.

  function soma(a, b) {
    return a + b;
  }

  const resultado = soma(2, 3);   // resultado vale 5
  console.log(resultado);          // 5

O que acontece na prática:
  1. soma(2, 3) é executada
  2. ela calcula 2 + 3 = 5
  3. o return "entrega" o 5 no lugar da chamada
  4. o 5 é guardado em resultado

Você pode usar o retorno direto, sem variável:
  console.log(soma(2, 3));        // 5
  const total = soma(2, 3) * 10;  // 50

⚠️ O return ENCERRA a função na hora.
Nada depois dele é executado:

  function teste() {
    return "primeiro";
    console.log("nunca roda");   // código morto!
  }

Função sem return devolve undefined:

  function garcom(prato) {
    console.log(prato);      // imprime, mas não retorna
  }

  const x = garcom("Pizza");
  console.log(x);            // undefined


========================================================
6. console.log DENTRO x return: A DIFERENÇA
========================================================
Essa é A dúvida mais comum de quem está aprendendo.

VERSÃO 1 - a função IMPRIME (efeito colateral):

  function garcom(prato, mesa) {
    console.log(`${prato} entregue na mesa ${mesa}`);
  }

  garcom("Carbonara", 10);   // já aparece na tela

VERSÃO 2 - a função DEVOLVE (o valor fica reaproveitável):

  function garcom(prato, mesa) {
    return `${prato} entregue na mesa ${mesa}`;
  }

  const retornoGarcom = garcom("Carbonara", 10);
  console.log(retornoGarcom);   // agora sim aparece

Por que a versão 2 costuma ser MELHOR:
  - o valor pode ser guardado, somado, comparado, enviado
    para outra função, escrito na tela via DOM...
  - a função não decide COMO o resultado é usado;
    quem chamou decide.

Regra prática:
  função que CALCULA algo   -> use return
  função que só EXIBE algo  -> pode usar console.log

  // calcula (retorna) — reutilizável
  function calcularDano(ataque, defesa) {
    return ataque - defesa;
  }

  // exibe (imprime) — final da linha
  function exibirDano(dano) {
    console.log(`Dano causado: ${dano}`);
  }

  exibirDano(calcularDano(50, 30));   // 20


========================================================
7. ARROW FUNCTION (SINTAXE MODERNA - ES6)
========================================================
Mesma ideia, escrita mais curta. Muito comum em React.

Clássica:
  function soma(a, b) {
    return a + b;
  }

Arrow (a função vira o valor de uma const):
  const soma = (a, b) => {
    return a + b;
  };

Arrow com retorno implícito (uma linha só, sem chaves e
sem a palavra return — o valor já é devolvido):
  const soma = (a, b) => a + b;

Com um parâmetro só, os parênteses são opcionais:
  const dobrar = numero => numero * 2;

Sem parâmetro nenhum, parênteses vazios obrigatórios:
  const ola = () => console.log("Olá!");

⚠️ DIFERENÇA IMPORTANTE (hoisting):
Função clássica pode ser chamada ANTES de ser declarada
no arquivo (o JS "iça" a declaração para o topo):

  soma(2, 3);                     // ✅ funciona
  function soma(a, b) { ... }

Arrow function NÃO — precisa ser declarada antes do uso:

  soma(2, 3);                     // ❌ erro!
  const soma = (a, b) => a + b;


========================================================
8. ESCOPO (VARIÁVEIS QUE VIVEM DENTRO DA FUNÇÃO)
========================================================
Variáveis criadas DENTRO de uma função só existem lá
dentro. Isso se chama escopo local.

  function calcular() {
    const segredo = 42;
    console.log(segredo);   // ✅ 42
  }

  calcular();
  console.log(segredo);     // ❌ ReferenceError

O contrário funciona: a função ENXERGA variáveis criadas
fora dela (escopo global):

  const emailCorreto = "lorenzo@gmail.com";
  const senhaCorreta = "senha123";

  function login(email, senha) {
    if (email === emailCorreto && senha === senhaCorreta) {
      console.log("Acesso Permitido!");
    } else {
      console.log("Usuário e/ou senha incorretos");
    }
  }

  login("lorenzo@gmail.com", "senha123");

Por que escopo é bom: cada função tem seu "espaço
privado", então variáveis internas de uma não atrapalham
as da outra. Duas funções podem ter um `let i` cada uma
sem conflito nenhum.


========================================================
9. PARÂMETROS COM VALOR PADRÃO
========================================================
Você pode definir um valor usado quando o argumento não
é informado:

  function garcom(prato, mesa = "balcão") {
    console.log(`Entregar ${prato} na ${mesa}`);
  }

  garcom("Pizza", 10);    // "Entregar Pizza na 10"
  garcom("Pizza");        // "Entregar Pizza na balcão"

Sem o padrão, o segundo caso mostraria "undefined".


========================================================
10. REST PARAMETERS (...) - Nº INDEFINIDO DE ARGUMENTOS
========================================================
Os três pontinhos juntam TODOS os argumentos recebidos
num array. Útil quando você não sabe quantos virão.

  function media(...numeros) {
    // numeros é um array: [10, 9, 6, 8]
    let soma = 0;

    for (const n of numeros) {
      soma += n;
    }

    return soma / numeros.length;
  }

  console.log(media(10, 9, 6, 8, 9, 1, 5, 7));   // 6.875
  console.log(media(25, 75));                     // 50

Regra: o rest parameter tem que ser o ÚLTIMO parâmetro.

  function exemplo(primeiro, ...resto) { ... }   ✅
  function exemplo(...resto, ultimo) { ... }     ❌

11. PADRÕES COMUNS (EXEMPLOS PRÁTICOS)
========================================================

Função que valida e retorna booleano:

  function ehMaiorDeIdade(idade) {
    return idade >= 18;
  }

  if (ehMaiorDeIdade(20)) {
    console.log("Pode entrar");
  }

Função com if/else e vários returns:

  function classificarNota(nota) {
    if (nota >= 9) {
      return "Excelente";
    } else if (nota >= 7) {
      return "Aprovado";
    } else {
      return "Reprovado";
    }
  }

  console.log(classificarNota(7.5));   // "Aprovado"

Função que calcula (o exercício do dano, refeito):

  function calcularDano(ataque, defesa, temEscudo) {
    if (ataque <= defesa) {
      return 0;
    }

    const diferenca = ataque - defesa;
    return temEscudo ? diferenca / 2 : diferenca;
  }

  console.log(calcularDano(50, 30, false));   // 20
  console.log(calcularDano(50, 30, true));    // 10
  console.log(calcularDano(20, 30, false));   // 0

Função chamando outra função:

  function calcularTotal(preco, quantidade) {
    return preco * quantidade;
  }

  function aplicarDesconto(valor, percentual) {
    return valor - (valor * percentual / 100);
  }

  const total = calcularTotal(50, 3);           // 150
  const comDesconto = aplicarDesconto(total, 10); // 135

12. ERROS CLÁSSICOS DE INICIANTE
========================================================

1. Declarar e esquecer de chamar:
   function ola() { console.log("Oi"); }
   // ...e nada acontece. Faltou: ola();

2. Esquecer os parênteses na chamada:
   ola;      ❌ isso apenas "menciona" a função
   ola();    ✅ isso executa

3. Confundir console.log com return:
   function soma(a, b) { console.log(a + b); }
   const x = soma(2, 3);   // x é undefined!
   // Para guardar o valor, a função precisa de return.

4. Trocar a ordem dos argumentos:
   garcom(10, "Pizza")   // vira prato=10, mesa="Pizza"

5. Código depois do return:
   return a + b;
   console.log("nunca executa");

6. Tentar usar variável interna fora da função:
   function f() { const x = 1; }
   console.log(x);   ❌ ReferenceError

7. Chamar uma arrow function antes de declará-la:
   soma(1, 2);                     ❌
   const soma = (a, b) => a + b;
